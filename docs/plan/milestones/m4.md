## Outcome

Boot a genuine Mix-generated Elixir/OTP release inside the guest and prove the final process-isolated Rust↔BEAM interoperability boundary.

## Scope

* Immutable Mix release payload and direct ERTS launcher manifest.
* `runtime_lab` supervision tree, supervisor-resilient in-memory demo state, worker generations, explicit BEAM/OS reset boundary, and restart-intensity behavior.
* Kernel-provisioned bounded IPC streams exposed to ERTS through fixed fd ports.
* Versioned four-byte-length-prefixed ETF protocol with bounded decoding.
* Rust loopback service, protocol fixtures, backpressure, disconnect, malformed-frame, and restart behavior.
* Serial logging and runtime identity evidence.

## Exit criteria

* The guest reports application, Elixir, OTP, emulator, and scheduler versions.
* Rust and Elixir exchange 1,000,000 bounded messages without corruption or deadlock.
* Malformed and oversized frames are rejected without killing either process.
* Endpoint closure yields bounded observable failure and recovery.
* The worker completes 1,000 deliberate supervised crash/restart cycles.
* A crash storm trips supervisor intensity as designed.
* GATE-4 approves the boundary for the GUI vertical slice.

## Implementation-readiness status — 2026-08-30

**Gate-blocked; not authorized.** Demo state is supervisor-resilient in-memory and intentionally resets on release/BEAM/OS restart. The unchanged upstream built-in fd port driver is allowed; project/dynamic drivers and NIFs are not. IPC has one framing owner, frozen packet/busy limits, bounded ETF/schema decoding, and exactly one terminal outcome per accepted action.
