# P1-11: Establish structured tracing, GDB/QMP control, and machine-readable test completion

[Architecture & Validation Plan](<../architecture.md>)

## Goal

Ensure hangs and regressions produce actionable evidence before musl and ERTS increase system complexity.

## Locked context

This work targets the project-owned AArch64 kernel on QEMU `virt`. Phase 1 is single-CPU except where a test explicitly prepares an SMP-safe interface. It must use the native project ABI, not the ERTS Linux-compatible personality.

## What to build

* Implement per-CPU bounded trace rings and structured serial records containing timestamp, CPU, process, thread, subsystem, event, and typed fields.
* Add counters for pages, context switches, IRQs, syscalls, handle/IPC state, faults, and unknown calls.
* Document QEMU GDB-stub attachment and commands to inspect CPUs, tasks, page tables, and traces.
* Add QMP VM lifecycle, screenshot placeholder, timeout, serial sentinel, and guest poweroff support to the test harness.

## Acceptance criteria

- [ ] Every Phase 1 test ends with a machine-readable pass/fail sentinel and build ID.
- [ ] On timeout, the harness preserves serial, QMP state, and GDB-ready process information.
- [ ] Trace overflow is counted and does not corrupt the kernel.
- [ ] Panic and user-fault artifacts can be decoded and linked to symbols from the exact build.

## Required tests and evidence

* Force a pass, assertion failure, kernel panic, user fault, and hang.
* Confirm the harness preserves distinct artifacts for each outcome.
* Run trace decoder and schema tests.

## Verification commands

* `just test-qemu`
* `just qemu-debug-smoke`
* `just evidence-check --phase 1`

## Dependencies

Blocked by: P1-03, P1-06, P1-08, P1-10.

## Out of scope

* ERTS, Elixir, musl/pthreads, GPU UI integration, networking, writable storage, and phone hardware.
* General POSIX/Linux compatibility or a production security claim.
* Broad optimization before correctness evidence.

## Completion rule

Do not mark Done until every acceptance item has durable evidence from the exact build. Preserve any failing seed or trace; never convert a flake into success by blind retry.

## Learning checkpoint

Explain the possible QEMU boot entry at EL1 or EL2, normalization into EL1, and the later exception return from EL1 into an isolated EL0 process, the invariant this slice protects, one race or memory-corruption failure mode, and how the tests expose it.
