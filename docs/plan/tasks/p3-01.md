# P3-01: Package and load the pinned upstream beam.smp inside the guest

[Architecture & Validation Plan](<../architecture.md>)

## Goal

Move the exact Phase 0 ERTS artifact into the immutable system image and reach its ELF entry point without changing it.

## Locked context

This phase must run the pinned, standard upstream ERTS artifact inside the custom AArch64 OS. Linux-hosted runs are comparison evidence only. The final runtime profile is non-JIT SMP with two normal schedulers on four guest vCPUs.

## What to build

* Add the pinned static `beam.smp`, minimal ERTS/OTP files, licenses, and build receipt to the system archive through `system.toml`.
* Declare the BEAM process with the compatibility ABI, read-only release-tree root, serial descriptors, memory limit, arguments, and environment.
* Extend the ELF/process loader only for image features actually present in the inspected artifact; keep every addition validated and tested.
* Emit milestones for image lookup, ELF validation, mappings, initial stack/auxv, process start, and first compatibility syscall.

## Acceptance criteria

- [ ] The guest maps and enters the exact hashed upstream artifact from Phase 0.
- [ ] The image inventory contains no host ERTS, dynamic loader, shared library, shell, or undeclared native code.
- [ ] All ELF/stack/auxv inputs match the target reference run.
- [ ] A malformed or substituted artifact fails before execution with a precise evidence record.

## Required tests and evidence

* Compare guest artifact hash and ELF inventory with the Phase 0 receipt.
* Run success, missing-artifact, bad-hash, malformed-ELF, and limit-exceeded cases.
* Save process mappings and first-syscall trace.

## Verification commands

* `just image-erts`
* `just inspect-image`
* `just run-erts-entry`

## Dependencies

Blocked by: GATE-2, P0-05.

## Out of scope

* Elixir application integration, GUI, JIT, networking, writable storage, NIFs, and phone hardware.
* Semantic patches to BEAM execution, scheduling, GC, process behavior, or loading.
* Host execution presented as guest success.

## Completion rule

Done requires evidence from the exact guest image and pinned upstream artifact. Any full-runtime defect must be reduced to a smaller contract test when feasible and must preserve the upstream-diff budget.

## Learning checkpoint

Explain how OS native threads relate to BEAM processes/schedulers, which host semantic this issue exercises, and how the evidence rules out a host-side or one-off success.

## Readiness-audit correction — 2026-08-30

* Runtime identity is two-factor: the image contains the exact P0-05 artifact hash/build receipt, and the running guest emits independently attributable identity. A banner alone does not prove which bytes executed.
* Re-run the complete ELF/static-native inventory at image assembly and at guest launch: no `PT_INTERP`, unapproved `DT_NEEDED`, host loader/library, host executable, writable overlay, 9p/shared folder, shell, `erlexec`, qemu-user bridge, or substituted ERTS is allowed.
* Load the exact artifact form actually built (`ET_EXEC` or static PIE) and only its proven relocation/TLS forms. Every text publication uses P1-14 cache/TLB maintenance and W^X; every mapping/auxv/HWCAP value must equal the frozen platform/contract.
* The process manifest pins personality, root/image object, argv/env, scheduler profile, memory/descriptor limits, production entropy requirement, fixed serial descriptors, CPU/affinity policy, and artifact hash. EL0 cannot alter these before entry.
* Compute and record hashes for source, patch set, toolchain, build receipt, `beam.smp`, every packaged native object/driver, release archive, process manifest, system image, and QEMU platform manifest.
* The native-code policy is: no unapproved dynamically loaded library/driver, no third-party or application NIF, and no undeclared compiled native object. Do not claim upstream ERTS literally contains no native implementation.
* Negative cases must include same filename/wrong bytes, valid alternate ERTS build, corrupted segment after image hash, unsupported ELF feature, auxv/platform mismatch, text mapped writable, deterministic entropy profile, and undeclared native object.
