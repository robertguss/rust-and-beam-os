# P0-08: Freeze the exact AArch64 BEAM host contract revision 1

[Architecture & Validation Plan](<../architecture.md>)

## Goal

Turn the exact target release trace into executable documentation for the custom kernel's ERTS compatibility personality.

## Locked context

This is Phase 0 of an emulator-first AArch64 OS POC. The deliverable must run against the pinned project artifacts and preserve the own-kernel hypothesis. Host-side programs are scaffolding and evidence only; they do not satisfy the final POC.

## What to build

* Trace the target Mix release through boot, IPC-ready idle, process stress, timers, GC, supervised crashes, crash-storm escalation, and shutdown on AArch64 Linux.
* Update `abi/beam-host.yaml` with exact AArch64 syscall numbers, admitted flags, return/error behavior, blocking semantics, caller, and evidence.
* Separate musl requirements from direct ERTS requirements and identify syscalls eliminated by disabled features.
* Make contract validation reject missing tests, unexplained entries, duplicated semantics, and unbounded flag sets.

## Acceptance criteria

- [ ] The contract covers every observed call in the complete reference workload.
- [ ] Every admitted operation has a named conformance test plan and evidence link.
- [ ] General subprocess, networking, dynamic loading, and broad `/proc` or device emulation are absent or explicitly fail GATE-0.
- [ ] A repeated trace produces no unexplained contract drift.

## Required tests and evidence

* Run the exact trace twice on the pinned target environment.
* Validate the YAML schema and evidence references.
* Conduct a manual source cross-check for thread, signal, VM, file, and poll families.

## Verification commands

* `just trace-target-release`
* `just beam-host-validate`
* `just beam-host-diff`

## Out of scope

* Do not implement a Linux or Android guest.
* Do not add networking, writable persistent storage, dynamic linking, third-party NIFs, or phone hardware.
* Do not weaken an acceptance test merely to make the spike pass.

## Readiness-audit correction — 2026-08-30

The host contract must include more than syscall numbers:

* Add startup/ELF/auxv clauses for `AT_PAGESZ`, `AT_HWCAP`, `AT_HWCAP2`, `AT_RANDOM`, `AT_EXECFN` if observed, program headers, entry address, TLS, stack alignment, argument/environment limits, and the exact CPU/machine baseline from P0-14.
* For every admitted call, record ABI number/signature, flags subset, blocking/interruption/restart behavior, memory ordering, copy-in/out rules, cancellation points, errno precedence, resource accounting, and concurrency/lifetime state machine.
* Distinguish calls made by musl startup, ERTS startup, steady state, shutdown, diagnostics, and excluded features. Unknown calls remain fail-closed.
* Treat `clone` + TLS + child-TID, futex, robust-list cleanup, signals, and `poll`/descriptor closure as coupled protocols rather than independent checklist rows.
* Link every relevant finding from P0-17. A syscall workaround that changes semantics is an explicit hypothesis failure or gate exception, never an undocumented compatibility implementation.
* Generate both positive and negative conformance tests from the contract and require a coverage report with no admitted behavior lacking a test oracle.
