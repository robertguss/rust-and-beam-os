# P3-05: Exercise Erlang processes, messages, timers, ETS, binaries, and GC

[Architecture & Validation Plan](<../architecture.md>)

## Goal

Demonstrate that the core BEAM execution model works inside the guest before enabling final SMP.

## Locked context

This phase must run the pinned, standard upstream ERTS artifact inside the custom AArch64 OS. Linux-hosted runs are comparison evidence only. The final runtime profile is non-JIT SMP with two normal schedulers on four guest vCPUs.

## What to build

* Create deterministic Erlang workloads for process spawn/link/monitor/exit, local messaging/selective receive, timers, ETS tables, binary creation/copying, and per-process garbage collection.
* Report reductions, process counts, run queues, memory categories, timers, GC counts, and kernel committed pages.
* Include normal, boundary, intentional process crash, timeout, allocation pressure, and cleanup cases.
* Keep the workload pure Erlang with no NIF, port, network, or Elixir dependency.

## Acceptance criteria

- [ ] All workloads produce their expected deterministic results and clean up their processes/tables/timers.
- [ ] An Erlang process crash remains within ERTS and does not become an OS process or kernel fault.
- [ ] Forced GCs and binary pressure do not corrupt data or produce unexplained committed-page growth.
- [ ] Timeout/timer behavior stays within the declared emulator tolerance.

## Required tests and evidence

* Run each workload repeatedly in the one-scheduler diagnostic profile.
* Cross-check selected results on reference ERTS.
* Save runtime and kernel metrics for every case.

## Verification commands

* `just test-erts-core-workloads`
* `just stress-erts-gc`

## Dependencies

Blocked by: P3-03.

## Out of scope

* Elixir application integration, GUI, JIT, networking, writable storage, NIFs, and phone hardware.
* Semantic patches to BEAM execution, scheduling, GC, process behavior, or loading.
* Host execution presented as guest success.

## Completion rule

Done requires evidence from the exact guest image and pinned upstream artifact. Any full-runtime defect must be reduced to a smaller contract test when feasible and must preserve the upstream-diff budget.

## Learning checkpoint

Explain how OS native threads relate to BEAM processes/schedulers, which host semantic this issue exercises, and how the evidence rules out a host-side or one-off success.

## Readiness-audit correction — 2026-08-30

* “Pure Erlang” means no application/third-party NIF, dynamically loaded driver, external port program, distribution/networking, or Elixir dependency. Built-in BIFs and upstream statically linked ERTS native implementation are expected and must remain in the native inventory.
* Define independent semantic oracles for spawn/link/monitor/exit ordering, selective receive, mailbox contents, timer cancellation/receipt races, ETS ownership/heir/cleanup subset, ref-counted and heap binary integrity, process dictionary if used, exception containment, and forced/natural GC. Do not compare inherently nondeterministic PIDs, reductions, GC timing, or scheduler order byte-for-byte.
* Each workload carries deterministic payload IDs/checksums and a terminal accounting record. Expected crashes are tagged and must terminate only the intended BEAM process; untagged exits, linked cascades, ERTS aborts, OS task deaths, signals, or kernel faults are failures.
* Exercise small/large/off-heap binaries, sharing/copying, message fanout, mailbox pressure, old/young heap collection, fullsweep, ETS insert/read/delete/table-owner death, timer create/cancel/fire, monitor `DOWN`, link trapping where admitted, and cleanup after allocation failure.
* Measure ERTS memory categories/allocators and kernel committed/reserved pages together. Attribute live workload data, allocator retention/fragmentation, immutable code, kernel metadata, and trace buffers separately; one aggregate counter cannot prove GC correctness.
* Apply explicit bounded pressure and allocation-failure behavior. An expected Erlang exception is acceptable only if ERTS remains healthy, later work succeeds, and all resources reach the workload's declared postcondition.
* Run single-scheduler diagnostics first, but preserve an identical workload for P3-06 final SMP and P3-09; any result that changes semantically with scheduler count is a blocker.
* Add metamorphic/reference checks: different legal scheduling/GC timing must produce equivalent terminal state, while injected message corruption, missing monitor cleanup, leaked ETS table, stale timer, and binary mutation must fail.
