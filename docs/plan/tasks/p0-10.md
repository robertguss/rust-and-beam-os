# P0-10: Implement and stress Linux-hosted Rust↔Elixir protocol endpoints

[Architecture & Validation Plan](<../architecture.md>)

## Goal

Prove the final interoperability semantics with ordinary Linux processes before involving the custom kernel.

## Locked context

This is Phase 0 of an emulator-first AArch64 OS POC. The deliverable must run against the pinned project artifacts and preserve the own-kernel hypothesis. Host-side programs are scaffolding and evidence only; they do not satisfy the final POC.

## What to build

* Implement a Rust endpoint using the planned narrow ETF subset and an Elixir endpoint using a fixed-fd port or equivalent pipe harness.
* Exercise handshake, semantic button events, coalesced pointer motion, snapshots, patches, acknowledgements, status, and metrics.
* Implement bounded queues, write/read readiness, malformed-frame rejection, version mismatch, endpoint closure, restart, and reconnection.
* Property-test the Rust codec against Erlang `term_to_binary`/`binary_to_term` behavior without permitting atom creation from untrusted data.

## Acceptance criteria

- [ ] One million bounded bidirectional messages complete without corruption, deadlock, unbounded memory growth, or scheduler blocking.
- [ ] Every malformed/oversized fixture is rejected while both endpoints remain alive.
- [ ] Button presses are never silently dropped; coalescing happens only for the documented event class.
- [ ] Endpoint death and restart reach the specified visible states within bounded time.
- [ ] Adding one optional field requires only localized schema/fixture/handler changes.

## Required tests and evidence

* Run deterministic load, fault, property, and leak tests.
* Record p50/p95/p99 round-trip latency and maximum queue depth on the reference host.
* Save the test seed and evidence bundle.

## Verification commands

* `just test-protocol`
* `just stress-protocol`
* `just fuzz-protocol`

## Readiness-audit correction — 2026-08-30

* Exercise the exact final fd-port contract on Linux: two independently directional OS streams/descriptors, fixed descriptor numbers, `{:fd, in_fd, out_fd}`, `:binary`, `{packet, 4}`, explicit `busy_limits_port`, and explicit `busy_limits_msgq`.
* The Elixir endpoint handles ETF payloads only because ERTS owns the packet prefix. The Rust endpoint handles exactly one four-byte prefix. Add a mandatory double-framing negative test.
* Set the 64 KiB cap before allocation/decoding on the Rust side. On Elixir, ensure the fd-stream/kernel boundary itself refuses oversized frames; `{packet,4}` alone does not supply an application packet-size limit for `open_port`.
* Decode untrusted payloads with `binary_to_term(payload, [:safe])` and then the strict v1 schema. Record atom-count, heap, mailbox, port-queue, and CPU bounds under malformed traffic.
* Test half-close/EOF, partial prefix/payload, peer death, write-after-close, simultaneous close, reconnect, queue saturation, suspended sender, owner death, and descriptor reuse.
* The Linux loopback result is scaffolding; it must use the same corpus, state machine, and framing ownership later required in the guest.
